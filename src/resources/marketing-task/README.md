# Маркетинговый агент (marketing-task)

AI-агент, который анализирует данные Google Search Console и Google Analytics 4 по сайту tenderwize.com, ставит конкретные задачи «что поправить на сайте», ведёт по каждой задаче историю и проверяет, сделана ли работа и дала ли она эффект.

## Возможности

- **Анализ и создание задач.** Вручную (кнопка «Run analysis» или `POST /marketing-tasks/adm/generate`) собирает данные GSC и GA4, вычисляет сигналы и просит LLM сформулировать до N задач с обоснованием в цифрах.
- **Защита от дублей.** Не создаёт задачу, если такая же уже открыта или была отклонена за последние 90 дней.
- **История задачи.** Журнал событий: создание, смены статуса, комментарии админа, заметки ИИ, снимки метрик, результаты проверок. ИИ читает его при каждой следующей обработке задачи.
- **Сопровождение задач.** При каждом анализе ИИ пересматривает открытые и недавно закрытые задачи: пишет заметку о прогрессе и обновляет краткую сводку (`summary`).
- **Проверка одной задачи.** Скачивает живую страницу и метрики именно её страницы или запроса, после чего ИИ выносит вердикт: сделано ли на сайте и есть ли эффект. Запускается кнопкой.
- **Админка.** Доска в стиле Jira с перетаскиванием между статусами и отдельная страница задачи с историей, комментариями и кнопкой проверки.

## Как это работает

### 1. Еженедельный анализ (`MarketingTaskGenerator.generate`)

1. **Сбор данных** (`MarketingDataService.collectSnapshot`). Период по умолчанию 28 дней, заканчивается 3 дня назад, потому что данные GSC становятся окончательными с задержкой. Сравнивается с предыдущим периодом такой же длины.
   - **GSC:** точные итоги сайта, страницы (до 25 000, с постраничной выгрузкой), запросы (до 5000), пары «запрос + страница» (до 10 000), страны и устройства; текущий и предыдущий период.
   - **GA4:** посадочные страницы (до 200), каналы и устройства: сессии, вовлечённость, средняя длительность, ключевые события.
2. **Сигналы считаются в коде, а не в LLM** (как в SEO-аудите):
   - `templates` / `locales`: клики, показы, CTR и позиция по шаблонам страниц (`classifyPage`: tender, award_tender, award_directory, buyer, contractor, industry, country, country_industry, guide, compare, pricing, app…) и по локалям URL;
   - `brand`: разделение бренд/небренд (`MARKETING_BRAND_TERMS`). Брендовые запросы исключаются из всех списков возможностей;
   - `strikingDistanceQueries`: небрендовые запросы на позициях 4–20 с ≥100 показов, с главной страницей запроса и `estimatedExtraClicks` (сколько кликов даст выход на позицию ~3);
   - `lowCtrPages`: страницы с CTR ниже половины ожидаемого для их позиции (`expectedCtrForPosition`), с `estimatedExtraClicks`;
   - `decliningPages`, `lostQueries`, `newQueries`, `weakRankingQueries` (позиция > 20);
   - `cannibalization`: запросы, по которым показывается несколько страниц сайта.
3. **Живые страницы** (`inspectedPages`, до 20): по одному образцу каждого основного шаблона (из страниц GSC, а если их нет — из посадочных GA4) и страницы главных возможностей. ИИ видит текущие title, meta, H1/H2, canonical, robots, hreflang, `lang` и число внутренних ссылок. Проблемы страницы считает код (`detectPageIssues`). Для локальных версий, которые сайт намеренно держит вне индекса (карта `INDEXABLE_LOCALES` в `marketing-task.utils.ts`, копия правил фронта `locale-indexing.ts`), проверяется только корректность этой настройки: noindex, canonical на `/en`, отсутствие hreflang. Для остальных страниц: `noindex`, canonical на другой URL, пустой серверный HTML, шаблонный title, длина title/meta, нет H1, мало текста, несовпадение `lang` и локали, нет hreflang, нет JSON-LD.
   Если показов за период меньше ~1000, агент переходит в «режим мало данных»: вместо CTR и позиций он проводит аудит индексации и шаблонов по этим проблемам.
4. **Контекст задач для LLM:**
   - *отслеживаемые задачи*: `new`, `in_progress` и `done`, закрытые за последние 60 дней. У каждой передаются `summary`, 12 последних записей истории, базовые метрики (первый снимок) и текущие метрики;
   - *отклонённые* за последние 90 дней: только чтобы не предлагать их повторно.
5. **Промпт** описывает сайт (бриф `SITE_BRIEF.md`: продукт и фичи, шаблоны URL, паттерны title/meta, блоки страниц, намеренные правила индексации по локалям, sitemap, события GA4, известные проблемы) и методику SEO-лида: сначала диагноз (спрос / позиции / CTR, бренд, локали, шаблоны), потом рычаги по кликам; повторяющаяся проблема в 3+ страницах одного шаблона даёт одну задачу на шаблон; перед правкой нужно свериться с живой страницей; общие советы запрещены.
6. **Ответ LLM**: `diagnosis` (общий разбор периода, возвращается в результате запуска и показывается в админке), `tasks` (новые задачи с готовым `deliverable`) и `reviews` (заметки по отслеживаемым задачам).
7. **Запись результатов:**
   - новые задачи проверяются по fingerprint (категория + нормализованная страница + запрос, или категория + шаблон) и создаются с записью `created` и снимком метрик в истории (у задач на шаблон — итоги шаблона);
   - по отслеживаемым задачам пишется `ai_review` (заметка + метрики, обновляется `summary`), а если заметки нет, то `metrics` (только метрики нового периода, без повторов для одного и того же периода).

Метрики задачи в этом режиме берутся из общих топ-списков. Страница или запрос с малым трафиком может остаться без метрик. Точные метрики даёт только проверка задачи.

### 2. Проверка задачи (`MarketingTaskChecker.check`)

1. **Живая страница** (`inspectMarketingPage`): HTTP-статус, `title`, `meta description`, H1/H2, `canonical`, `robots`, типы JSON-LD, число слов, число упоминаний запроса задачи в title, description, H1 и тексте. Относительный путь достраивается до полного URL по `GSC_SITE_URL`. У задачи на шаблон без `pageUrl` проверяется страница-образец: первая ссылка этого шаблона из `evidence`, `deliverable`, `acceptanceCriteria` или `description`. По ней же считаются метрики.
2. **Точечные метрики** (`MarketingDataService.collectTaskMetrics`): запросы GSC и GA4 с фильтром по странице и/или запросу. Сравниваются последние N дней (по умолчанию 14) с N днями до них. Если в задаче указаны и страница, и запрос, приходят метрики пары и метрики всей страницы.
3. **LLM** получает задачу, 20 последних записей истории, базовые метрики, свежие метрики и данные страницы. Возвращает:
   - `verdict`: `implemented` / `partially` / `not_implemented` / `unclear`. Живой странице ИИ доверяет больше, чем комментариям;
   - `effect`: `positive` / `negative` / `none` / `too_early` / `unknown`. ИИ учитывает, что GSC показывает эффект через 2–4 недели;
   - `note` (что проверено и какой вывод) и `summary`.
4. В историю пишется запись `check`, обновляется `summary`. **Статус задачи не меняется**, его меняет админ.

### 3. Автоматическая проверка (`MarketingTaskChecker.checkDue`)

Крон прогоняет проверку по задачам, где она имеет смысл:
- `in_progress`: сделано ли уже;
- `done`, закрытые 14–56 дней назад: есть ли эффект;
- только задачи со страницей, запросом или шаблоном;
- задача не проверялась последние 7 дней (ручная проверка тоже считается).

За один запуск делается не больше 20 проверок, по одной за раз. Первыми идут задачи, которые не проверялись никогда или проверялись давно. Ошибка на одной задаче не останавливает остальные.

## Модель задачи (`marketing_tasks`)

| Поле | Описание |
|---|---|
| `title`, `description` | Что сделать, конкретно |
| `category` | `ctr`, `content`, `content_gap`, `cannibalization`, `internal_linking`, `technical`, `conversion`, `traffic_drop`, `tracking` |
| `scope`, `template` | Что меняет задача: `page` / `template` / `site`, и шаблон страниц |
| `deliverable` | Готовый результат: точные title/meta, шаблоны с плейсхолдерами и примерами, список H2, ссылки с анкорами |
| `acceptanceCriteria` | Как проверить на живом сайте, что сделано; по нему сверяется проверка задачи |
| `estimatedClicks` | Доп. клики за период, из `estimatedExtraClicks` снимка |
| `priority` | `high` / `medium` / `low` |
| `status` | `new` → `in_progress` → `done` / `rejected` |
| `source` | `ai` или `manual` |
| `pageUrl`, `query` | Цель задачи: страница и/или поисковый запрос |
| `evidence` | Цифры, которые обосновывают задачу |
| `expectedImpact` | Ожидаемый эффект |
| `fingerprint` | Ключ дедупликации |
| `periodStart`, `periodEnd` | Период данных, на которых создана задача |
| `llmProvider`, `llmModel` | Какая модель создала задачу |
| `notes` | Свободные заметки админа |
| `summary` | Текущее состояние задачи; переписывается ИИ при ревью и проверке |
| `history` | Журнал событий, хранятся последние 100 записей |
| `completedAt` | Когда задача переведена в `done` |

### Записи истории

| `type` | Кто пишет | Что содержит |
|---|---|---|
| `created` | ai / admin | Создание; у AI-задач снимок метрик, от которого считается эффект |
| `status_changed` | admin | Новый статус (только при реальной смене) |
| `comment` | admin | Что сделано на сайте, блокеры, вопросы; ИИ это читает |
| `ai_review` | ai | Заметка анализа + метрики |
| `metrics` | system | Метрики нового периода без заметки |
| `check` | ai | Вердикт, эффект, заметка, точечные метрики |

У каждой записи есть `at`, `actor` и, где это применимо, `text`, `metrics` (clicks, impressions, ctr, position, sessions, engagementRate, keyEvents), `periodStart`/`periodEnd`, `status`, `verdict`, `effect`.

## API (только для админа, `AdminAccessGuard`)

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/marketing-tasks/adm/generate` | Запустить анализ (`days` 7–90, `maxTasks` 1–30, `language`) |
| `GET` | `/marketing-tasks/adm` | Список задач: фильтры `status`, `priority`, `category`; `sort=priority\|recent`; пагинация. Вместо истории отдаётся `historyCount` |
| `POST` | `/marketing-tasks/adm` | Создать задачу вручную |
| `GET` | `/marketing-tasks/adm/:id` | Задача целиком, с историей |
| `PATCH` | `/marketing-tasks/adm/:id` | Изменить title, description, status, priority, notes |
| `POST` | `/marketing-tasks/adm/:id/comments` | Добавить комментарий в историю (`text`) |
| `POST` | `/marketing-tasks/adm/:id/check` | Проверить задачу (`days` 7–90, `language`); возвращает `{ task, dataErrors }` |
| `DELETE` | `/marketing-tasks/adm/:id` | Удалить задачу (лучше ставить `rejected`, чтобы ИИ не предложил её снова) |

## Админка

- **Доска** `/admin/marketing-tasks`: колонки New / In progress / Done / Rejected. Статус меняется перетаскиванием карточки. Есть фильтры по приоритету и категории. Открытые задачи отсортированы по приоритету (до 100 в колонке), закрытые — по свежести (до 30). Под доской панели «Run analysis» и «Add task».
- **Страница задачи** `/admin/marketing-tasks/:id`:
  - слева описание, данные, ожидаемый эффект, блок «Progress» (`summary`), поле «Add to history» и лента истории (сначала новые);
  - справа статус и приоритет, цель задачи, источник, даты, кнопка **Run check** с выбором периода (7/14/28 дней), Edit и Delete.

## Настройка

Переменные в `.env`:

| Переменная | Назначение |
|---|---|
| `GOOGLE_SERVICE_ACCOUNT_KEY_FILE` / `GOOGLE_SERVICE_ACCOUNT_JSON` | Ключ service account Google |
| `GSC_SITE_URL` | Свойство GSC: `https://tenderwize.com/` или `sc-domain:tenderwize.com`. Из него же достраиваются полные URL страниц |
| `GA4_PROPERTY_ID` | Числовой id свойства GA4 |
| `MARKETING_TASKS_LANGUAGE` | Язык заметок проверки, если `language` не передан (по умолчанию `ru`) |
| `MARKETING_BRAND_TERMS` | Брендовые термины через запятую (по умолчанию `tenderwize,tenderwise,tender wize`) |

Email service account нужно добавить пользователем в свойство GSC (уровня Restricted достаточно) и Viewer в свойство GA4. LLM используется через `LlmAnalysisService.createDeepJsonResponse`, то есть провайдер и модель глубокого анализа.

## Ограничения

- Анализ берёт метрики задач из топ-списков, поэтому у малотрафиковых страниц и запросов метрик может не быть. Точные данные даёт только проверка.
- Проверка видит только HTML, который отдаёт сервер. Изменения вне страницы (ссылки, скорость, индексация) и страницы, которые рендерятся на клиенте, дадут вердикт `unclear`.
- У задач на шаблон метрики (итоги шаблона) пишутся при анализе.
- Итоги по шаблонам и локалям считаются по выгруженным страницам (до 25 000). Если страниц с показами больше, хвост не учитывается; точные итоги сайта — в `totals`.
- Статусы ИИ не меняет, вердикты носят рекомендательный характер.
- Одна проверка — это один вызов LLM и до 6 запросов к Google API. Анализ — один вызов LLM и около 11 запросов.
